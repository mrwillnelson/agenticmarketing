## Annotations

1. The baseline is not wrong; it is unusable. "Keep editing for concision" changes nothing about the next draft, so next cycle produces the same 6 edits again. The changeset moves each recurring edit into the pack file that prevents it, which is what makes the pack compound.
2. Every proposal carries a count and dates, so it takes one glance to verify and one word to approve or reject. Note what did NOT become a proposal: the 2-instance patterns went to the watch list, per the 3+ rule.
3. The voice-model paragraph-rhythm item is phrased as a question, not a proposal. The data cannot say whether the pack is stale or the user is moving; only the user can, and the two answers lead to opposite fixes.
4. The teardown-pillar observation stays an observation. Four vocabulary cuts can rewrite the lexicon; no amount of style evidence may rewrite strategy files. The skill asks.
5. Everything is checkbox-gated and nothing is applied. After approval, each accepted line lands verbatim and each touched file gets a dated changelog line, e.g. `- 2026-07-11 improve-my-pack: added "incredible" to never-says (cut in 4 of 6 drafts)`.
